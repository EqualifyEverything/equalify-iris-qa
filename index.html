PDF-to-HTML accessibility test suite

Nine standalone test cases for evaluating semantic inline styling, source page boundaries, and page navigation in ordinary HTML documents. No EPUB reader, dependencies, or server-side code needed. Converted from the source document with Chatgpt then edited manually to fix some minor errors. Used Claude code to add linting and prettier, fix source formatting consistantly across the codebase, and ask questions about gh pages operations for organization owned repos.

Every case uses similar example content and simulates four source PDF pages. These are HTML reading-flow tests, not a visual PDF reproduction. In the HR and section cases, cross-page content must be split, which is itself part of the comparison.

  • 1B: CSS-only spans

Set 2: Page boundaries

  • 2A: Inline doc-pagebreak spans
  • 2B: HR elements with doc-pagebreak
  • 2C: Named section per page

Set 3: Page navigation

  • 3A: No page navigation (control)
  • 3B: Static nav landmark with links
  • 3C: Nav landmark inside a disclosure
  • 3D: JavaScript-generated nav landmark

Suggested test tasks

  1. Read from the start through each page boundary and report whether the page change is announced and whether it interrupts the sentence, list, or table.
  2. Navigate by headings, lists, tables, and landmarks and describe unexpected differences.
  3. For Set 3, find the navigation controls, jump to page 3, and report where reading resumes.
  4. For 3D, disable JavaScript and check whether the page markers are still present but navigation controls disappear.
  5. Record browser, browser version, OS, assistive technology/version, and whether you were using browse or focus mode.

Important: these examples deliberately avoid styling the span markers as blocks. That is a separate experiment worth adding if needed. Page fragment link behavior and screen reader announcements can differ.
